# نشر Bank Match على Vercel

## ما تم تجهيزه

الواجهة وواجهة API تعملان على المشروع والنطاق نفسيهما.
`vercel.json` يوجه `/api/*` إلى دالة Express، ويخدم الملفات الثابتة،
ويعيد صفحات مثل `/products/nbk-247` إلى تطبيق الواجهة.
البناء لا يتصل بقاعدة البيانات ولا يغير مخططها.

## إعدادات الاستيراد

- Root Directory: `./` (جذر المستودع، وليس مجلد الواجهة).
- Framework Preset: `Vite`.
- Build Command: `npx --yes pnpm@10.26.1 run build:vercel`.
- Output Directory: `artifacts/bank-match/dist/public`.
- Install Command: `npx --yes pnpm@10.26.1 install --frozen-lockfile`.
- Node.js: `24.x` (الإصدار الذي اختبر به البناء والخادم).
- ارفع ملفات الإعداد الجديدة إلى GitHub أولًا. لا تختبر هذه الإعدادات على نسخة قديمة من المستودع.

القيم موجودة أيضًا في `vercel.json`. احذف أي تجاوزات قديمة في لوحة Vercel تخالفها.
إصدار pnpm مثبت صراحةً؛ تجاوز التثبيت بأمر `pnpm install` وحده قد يختار
Vercel له إصدارًا قديمًا لا يدعم كتالوج حزم هذا المستودع.

## قاعدة البيانات — مطلوبة

لا ينشئ Vercel قاعدة PostgreSQL تلقائيًا بمجرد استيراد هذا المستودع.
استخدم قاعدة مخصصة للإنتاج يمكن الوصول إليها من Vercel، واتصالًا مجمعًا
(pooled connection) إذا وفره مزود قاعدة البيانات.
لا تستخدم قاعدة التطوير للإنتاج دون قرار واضح، ولا ترسل رابط الاتصال في المحادثة.

أضف `DATABASE_URL` في **Vercel → Settings → Environment Variables**،
باعتباره متغيرًا سريًا للخادم، وليس متغيرًا يبدأ بـ `VITE_`.
استخدم قاعدة منفصلة لمعاينات الفروع؛ لا تربط Preview ببيانات الإنتاج دون قصد.

### تجهيز الجداول قبل أول تشغيل

من جهاز موثوق أو بيئة إدارة محمية، مع `DATABASE_URL` مضبوطًا سرًا على قاعدة
الإنتاج المطلوبة، نفذ مرة واحدة:

```sh
pnpm install --frozen-lockfile
pnpm --filter @workspace/db run push
```

راجع تغييرات المخطط المعروضة قبل الموافقة. هذا الأمر قد يعدل جداول موجودة؛
لا تنفذه على قاعدة أخرى أو قاعدة تحتوي بيانات مهمة دون نسخة احتياطية.
لا يوجد `--force` ولا ترحيل تلقائي في البناء أو طلبات الزوار.
عند أول طلب، يملأ الخادم الكتالوج الرسمي من المصدر الحالي ويحافظ على تحديثاته
وفق مراجعات الكتالوج. لا توجد بيانات مستخدمين تجريبية.

إذا لم تجهز القاعدة والجداول، يرجع الخادم `503 SERVICE_NOT_READY` بدل صفحة
تبدو ناجحة أو نتائج مصرفية مزيفة. لا يمكن اعتبار النشر مكتملًا قبل إعداد القاعدة.

## OpenRouter — اختياري

تعمل المطابقة والحسابات والأسباب المحلية بدون مفتاح AI.
لتفعيل الشرح الاختياري خارج Replit، أضف مفتاحك الخاص باسم
`OPENROUTER_API_KEY` في متغيرات Vercel السرية.
المسار المجهز لـ Vercel يستخدم مفتاح OpenRouter الخاص بك؛ لا يحتاج نقل مفاتيح
تكامل Replit إلى منصة أخرى.
لا تضف مفتاحًا في الواجهة أو باسم يبدأ بـ `VITE_`، ولا تضع أسرارًا في Git.

## فحص النشر بعد موافقتك

1. `GET /api/healthz` و`GET /api/products` يعيدان JSON ناجحًا.
2. افتح `/products/nbk-247` مباشرة ثم أعد تحميله.
3. أكمل الاختبار وتحقق من `POST /api/recommendations` وتغير الترتيب.
4. افتح `/api/not-a-route`: يجب ألا يرجع HTML الواجهة.
5. تحقق من المطابقة دون مفتاح AI، ثم الشرح الاختياري إذا أضفته.

اختبار البناء محليًا لا يثبت نجاح الاتصال بقاعدة الإنتاج أو نجاح إعداد حساب
Vercel. لم ينفذ الوكيل نشرًا أو رفعًا إلى GitHub نيابةً عن المستخدم.
